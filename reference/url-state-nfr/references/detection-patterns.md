# Detection Patterns — Five-Step Analysis Algorithm

This document defines the analysis algorithm that analyzer sub-agents follow when examining each component in their batch. Apply these steps in order for every file.

---

## Step 1: Identify All State Declarations

Find every instance of stateful value creation or consumption in the component:

### Direct State Hooks
- `useState` / `useReducer` — local component state

### Context Consumption
- `useContext` — React context consumption (note which context)

### External Store Hooks
- `useSelector`, `useStore`, `useDispatch` — Redux
- `useStore` (from zustand), or custom hooks generated by `create()` from `zustand` — Zustand
- `useAtom`, `useAtomValue`, `useSetAtom` — Jotai
- `useRecoilState`, `useRecoilValue` — Recoil
- `useSnapshot`, `useProxy` — Valtio
- Direct store subscriptions: `store.getState()`, `store.subscribe()`

### Custom Hooks
- Any `use[Something]` hook that returns a stateful value used in conditional rendering
- Pay special attention to hooks named `useDrawer()`, `useModal()`, `useSidebar()`, `usePanel()`, `useStepper()` — these often wrap `useState` internally and return `{ isOpen, open, close }`. The abstraction hides local state but the state is still not URL-sourced. These ARE violations.

### URL State Hooks (Compliant — Do Not Flag)
- `useSearchParams`, `useParams` — React Router
- `useRouter`, `usePathname`, `useSearchParams` — Next.js
- `useLocation`, `useHash` — various routers
- `useQueryState`, `useQueryStates` — nuqs
- `useSearch`, `useParams`, `useNavigate` (with search params) — TanStack Router
- `useLoaderData`, `useActionData` — Remix / React Router v6+
- Any custom hook that internally reads from URL/query parameters

---

## Step 2: Determine if State Controls View Rendering

For each state value found in Step 1, trace its usage through the component. Look for these conditional rendering patterns:

### Pattern A: Logical AND
```tsx
{isOpen && <DrawerComponent />}
{showSidebar && <Sidebar />}
```

### Pattern B: Ternary
```tsx
{activeTab === 'settings' ? <SettingsPanel /> : <MainPanel />}
```

### Pattern C: Early return
```tsx
if (!isVisible) return null;
return <FullPageOverlay />;
```

### Pattern D: Prop passing to view primitives
```tsx
<Modal open={isModalOpen} onClose={handleClose} />
<Drawer visible={showDrawer} />
<Sidebar collapsed={isSidebarCollapsed} />
```

### Pattern E: Switch or object lookup
```tsx
switch (currentStep) {
  case 1: return <StepOne />;
  case 2: return <StepTwo />;
}
```

### Pattern F: Array index or map-based view selection
```tsx
const panels = [<Overview />, <Details />, <Settings />];
return panels[activeIndex];
```

### Prop Names That Signal View State Control

When state is passed as a prop to a child component, these prop names strongly indicate view-state control:
`open`, `visible`, `show`, `isOpen`, `active`, `expanded`, `collapsed`, `hidden`, `displayed`

### Classify What Is Being Conditionally Rendered

1. **Named view primitive** — component name matches: Modal, Dialog, Drawer, Sheet, Sidebar, SideNav, SidePanel, TabPanel, TabContent, Accordion, AccordionPanel, Stepper, Step, Overlay, Collapse, Panel, Menu (navigation context)
2. **UI library import** — component is imported from a UI library (MUI, Radix, Ant Design, Chakra, Headless UI, Mantine, shadcn, or a custom internal component library)
3. **Substantial JSX block** — even without keyword matches, a large conditional JSX section that changes page layout is a candidate

---

## Step 3: Classify the State Source

For each flagged state value, record its source:

| Source | Description | Who Owns the Violation? |
|--------|------------|------------------------|
| `local` | `useState`, `useReducer` | This component |
| `context` | `useContext` — note which context | The context provider |
| `store` | Redux/Zustand/Jotai/Recoil/Valtio — note which store/atom | The store definition |
| `prop` | Received as a prop from parent | The parent component (flag here but note violation root is upstream) |
| `url` | `useSearchParams`, `useParams`, nuqs, TanStack Router, etc. | **Compliant — do not flag** |

### Partial Compliance

If a component uses URL state for some view controls but local/store state for others, classify as `partial`. Example: tabs are URL-driven but a drawer in the same component uses `useState`. List both the compliant and non-compliant controls.

---

## Step 4: Assess Cross-Cutting Impact

Determine the fix scope by examining how the state flows:

### Isolated
- State is local (`useState`) and used only within this component
- Fix touches only this file
- Example: `const [isModalOpen, setIsModalOpen] = useState(false)` used inline

### Cross-Cutting
- State is owned by this component but passed as props to children
- Fix requires changes to this file and its direct children
- Example: Parent passes `isDrawerOpen` to `<OrderDrawer open={isDrawerOpen} />`

### Root Refactor
- State lives in a Context Provider or global store
- Fixing means removing view state from shared state and migrating all consumers to URL state
- Example: A `SidebarContext` distributes `isSidebarOpen` to the layout, header, and multiple page components

Record affected components: list every child or consumer that would need changes.

---

## Step 5: Assign Confidence

Apply the confidence rubric:

| Score | Criteria |
|-------|----------|
| 0.9–1.0 | Unambiguous view primitive name (Modal, Drawer, Sidebar) + conventional state naming (`isOpen`, `showModal`) |
| 0.7–0.89 | Substantial UI section, suggestive component name, clear conditional rendering |
| 0.5–0.69 | Generic component name, ambiguous state naming, moderate conditional block |
| 0.3–0.49 | Weak signal, could be ephemeral UI |
| Below 0.3 | Do not include — it's noise |

Before finalizing, re-check each finding against the exclusion list. Form state and loading state are the #1 and #2 false positive sources.

---

## Output Format Per Finding

```json
{
  "file_path": "src/features/orders/OrderPage.tsx",
  "component_name": "OrderPage",
  "line_number": 23,
  "confidence": 0.92,
  "violation_type": "full",
  "state_declaration": "const [isDrawerOpen, setIsDrawerOpen] = useState(false)",
  "state_source": "local",
  "controlled_element": "OrderDrawer (imported from ./OrderDrawer)",
  "controlled_element_type": "Drawer",
  "rendering_pattern": "{isDrawerOpen && <OrderDrawer order={selectedOrder} onClose={() => setIsDrawerOpen(false)} />}",
  "fix_scope": "cross-cutting",
  "affected_components": ["OrderDrawer"],
  "suggested_fix": "Replace useState with searchParams.get('drawer') and update toggle handler to use setSearchParams."
}
```

For partially compliant components, add:

```json
{
  "violation_type": "partial",
  "compliant_controls": ["activeTab — sourced from useSearchParams"],
  "non_compliant_controls": ["isFilterPanelOpen — sourced from useState"]
}
```
